# Project Context
This is an inventory management system for a warehouse operations team.
The API is built with Node.js, TypeScript, and Express with a PostgreSQL database.
The team consists of developers, a DBA, a PM, a tech writer, and various stakeholders.

## Team Structure
- 4 backend developers
- 1 DBA (part-time, shared with another team)
- 1 PM / Product Manager
- 1 Tech Writer (shared with another team)
- Stakeholders: warehouse operations manager, finance lead

## When Helping Me
- Frame technical topics in terms of team impact, delivery risk, and business value
- Summarize complex technical details — I need the "so what" not the implementation details
- When referencing code changes, focus on what changed, why, and what it affects
- Use bullet points and tables — I scan, I don't read paragraphs
- Include effort estimates and timeline implications when relevant
- Flag dependencies between work items or team members

## Communication Preferences
- Status updates should follow the format in reports/sample-status-report.md
- Performance reviews follow the template in reviews/self-assessment-template.md
- Keep summaries under 200 words with a TL;DR at the top
- When listing risks, always pair with a mitigation and an owner
- When discussing trade-offs, present as a table: Option / Pros / Cons / Recommendation
